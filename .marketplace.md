[orchestrator] ## Shared Project Architecture & Specifications
[orchestrator] - Region: Ortenaukreis (Ortenau), Baden-Württemberg, Germany (Bounding Box: South 48.18, West 7.75, North 48.72, East 8.35; Center: 48.47, 7.95).
[orchestrator] - Project Structure:
[orchestrator]   - `Frontend/` : Classic HTML, CSS, Vanilla JS (`index.html`, `style.css`, `app.js`).
[orchestrator]   - `Backend/` : Node.js Express server (`package.json`, `server.js`) serving `Frontend/` statically and exposing `/api/*` endpoints on port `3000`.
[orchestrator]   - `Backend/Geoservices/` : OpenStreetMap Geoservices (`osmService.js`, `ortenauLocations.js`) using OpenStreetMap APIs (Overpass API, Nominatim API, Panoramax OSM Street-Level API) + Haversine distance calculation + Ortenau boundary checks.
[orchestrator]   - `config/` : Docker configuration (`config/Dockerfile`).
[orchestrator]   - `./docker-compose.yaml` : Root Docker Compose file to launch the full stack.
[orchestrator] - Shared API Contract (`http://localhost:3000`):
[orchestrator]   - `GET /api/health` -> `{ status: "ok", region: "Ortenaukreis" }`
[orchestrator]   - `GET /api/region` -> Returns Ortenau region bounding box, center, polygon/boundary coordinates, and metadata.
[orchestrator]   - `GET /api/location/random` -> Returns a random street-level location strictly within Ortenau (`lat`, `lng`, `roundId`, `heading`, `osmContext` with real roads/buildings/POIs/signs from OpenStreetMap Overpass API, and `streetView` / `panorama` metadata).
[orchestrator]   - `POST /api/guess` -> Accepts `{ actual: { lat, lng, roundId }, guess: { lat, lng } }` (or flat `{ actualLat, actualLng, guessLat, guessLng }`) and returns `{ distanceMeters, distanceKm, distanceFormatted, score, maxScore, actual, guess }`.

[docker] ## Docker Subagent Implementation & Findings
[docker] - **Base Image Chosen**: `node:22-alpine`
[docker]   - Lightweight Alpine Linux distribution with Node.js 22 LTS.
[docker]   - Node 22 includes native `fetch` and `AbortSignal.timeout`, used by both the OpenStreetMap Geoservices (`Backend/Geoservices/osmService.js`) and the container `HEALTHCHECK`.
[docker]   - Single-container architecture: Express (`Backend/server.js`) serves both the `/api/*` endpoints and the static `Frontend/` files (`index.html`, `style.css`, `app.js`), and the game is stateless (no database container required).
[docker] - **Dockerfile (`config/Dockerfile`)**:
[docker]   - Sets `WORKDIR /app/Backend` and copies `Backend/` to `/app/Backend/` and `Frontend/` to `/app/Frontend/` so that `path.join(__dirname, '../Frontend')` in `Backend/server.js` resolves identically to local development.
[docker]   - Installs production dependencies only via `npm install --omit=dev`.
[docker]   - Runs as the non-root `node` user on port `3000` (`ENV PORT=3000`, `ENV NODE_ENV=production`).
[docker]   - Configures `HEALTHCHECK` against `http://localhost:3000/api/health`.
[docker] - **Docker Compose (`./docker-compose.yaml`)**:
[docker]   - Service `ortenau-guesser` builds from root context `.` using `dockerfile: config/Dockerfile`.
[docker]   - Maps host port `${PORT:-3000}:3000` and sets `OSM_USER_AGENT=OrtenauGuesser/1.0 (Baden-Wuerttemberg GeoGame)` to comply with OpenStreetMap (Nominatim/Overpass/Panoramax) API usage policies.
[docker]   - Launch command: `docker compose up --build` (or `docker compose up -d --build`).

[backend] ## Backend & OpenStreetMap Geoservices Implementation
[backend] - Created `Backend/package.json` (`ortenau-guesser-backend`, entry `server.js`, script `npm start` -> `node server.js`, dependencies: `express`, `cors`, using Node built-in `fetch`).
[backend] - Created `Backend/Geoservices/ortenauLocations.js`:
[backend]   - Defined `ORTENAU_REGION` (OSM Relation ID `62608`, bounding box `south: 48.18, west: 7.75, north: 48.72, east: 8.35`, center `48.4719, 7.9498`, 17-point Ortenaukreis polygon, and 25 municipalities).
[backend]   - Implemented `isPointInOrtenau(lat, lng)` with ray-casting polygon check and bounding-box verification.
[backend]   - Curated 28 street-level locations strictly inside Ortenaukreis (`Offenburg`, `Gengenbach`, `Lahr/Schwarzwald`, `Kehl`, `Achern`, `Oberkirch`, `Haslach im Kinzigtal`, `Wolfach`, `Hornberg`, `Ettenheim`, `Rust`, `Sasbachwalden`, `Zell am Harmersbach`, `Oppenau`, `Durbach`, `Hausach`, `Kappelrodeck`, `Rheinau`, `Bad Peterstal-Griesbach`, `Seelbach`, `Appenweier`, `Schutterwald`, `Neuried`, `Meißenheim`, `Friesenheim`, `Seebach/Mummelsee`, `Gutach/Vogtsbauernhof`, `Renchen`) with baseline OSM roads, buildings, street signs, and landmarks.
[backend] - Created `Backend/Geoservices/osmService.js`:
[backend]   - `fetchOverpassSurroundings(lat, lng, radiusMeters)`: Queries OpenStreetMap Overpass API (`https://overpass-api.de/api/interpreter`) for nearby `highway`, `building`, `amenity`, `tourism`, `historic`, `natural`, and `landuse` elements and calculates compass bearings and distances in meters.
[backend]   - `fetchReverseGeocode(lat, lng)`: Queries OpenStreetMap Nominatim API (`https://nominatim.openstreetmap.org/reverse?format=jsonv2`) for street, town/municipality, postcode, and county (`Ortenaukreis`).
[backend]   - `fetchStreetLevelImagery(lat, lng)`: Queries Panoramax (`https://api.panoramax.xyz/api/search`) and Wikimedia Commons Geosearch (`https://commons.wikimedia.org/w/api.php`) for open street-level imagery alongside 360° OSM procedural streetview data.
[backend]   - `calculateDistanceAndScore(actualLat, actualLng, guessLat, guessLng)`: Computes Haversine distance (`distanceMeters`, `distanceKm`, `distanceFormatted`), bearing, `guessInOrtenau`, and score (`0` to `5000`, exponential decay `5000 * exp(-distanceKm / 12)`).
[backend] - Created `Backend/server.js`:
[backend]   - Express server listening on `0.0.0.0:3000` (`process.env.PORT || 3000`), serving static files from `../Frontend`.
[backend]   - Exposed `GET /api/health`, `GET /api/region`, `GET /api/location/random`, `GET /api/location/surroundings`, and `POST /api/guess`.

[frontend] ## Frontend Subagent Implementation & Findings
[frontend] - **Created Files (`Frontend/`)**:
[frontend]   - `Frontend/index.html`: Classic HTML5 structure including Leaflet 1.9.4 (OpenStreetMap) and Pannellum 2.5.6 (WebGL 360° Equirectangular Panorama Viewer).
[frontend]   - `Frontend/style.css`: Responsive Black Forest / Rhine Valley / Baden Gold glassmorphism UI styling, compass tape HUD, and expandable bottom-right mini-map (`340px` compact -> `500px` on hover/pin toggle).
[frontend]   - `Frontend/app.js`: Vanilla JavaScript singleplayer game engine without persistence.
[frontend] - **Game Rules & UI Screens Implemented**:
[frontend]   - **Main Menu (`#main-menu`)**: Features Ortenau Guesser branding, game mode selector (`Standard 5 Rounds` vs `Endless Free Play`), `Start Game in Ortenau` CTA, `Game Rules` modal (`#rules-modal`), and a live OpenStreetMap region preview map (`#menu-preview-map`) displaying the 17-point Ortenaukreis boundary polygon.
[frontend]   - **Fixed-Point 360° StreetView (`#game-screen`, `#pano-viewer`)**:
[frontend]     - Dynamically renders a 4096x2048 360° equirectangular street-level panorama (`generateOsmEquirectangularPanorama(locationData)`) from the backend's OpenStreetMap Overpass context (`roads`, `buildings`, `signs`, `landmarks`, `terrain`, `elevation`) and loads it into Pannellum.
[frontend]     - Player is strictly fixed to the drop point: can pan 360° horizontally, tilt vertically, and zoom in on street signs/buildings/terrain, with movement disabled.
[frontend]     - Live 360° compass bar (`#compass-tape` & `#compass-readout`) tracks camera yaw in real time.
[frontend]     - Includes an optional `Street Cam / Photo` tab (`#view-mode-streetembed`) for Panoramax/Wikimedia/StreetView comparison and a collapsible `Field Observations` OSM clue drawer (`#clue-drawer`).
[frontend]   - **Bottom-Right OpenStreetMap Mini-Map (`#minimap-wrapper`, `#guess-map`)**:
[frontend]     - Positioned in the bottom-right corner, bounded to the Ortenaukreis region (`maxBounds` & highlighted boundary polygon), expanding smoothly on hover or toggle button.
[frontend]     - Clicking places the guess marker and enables `#submit-guess-btn` (`Lock In Guess`).
[frontend]   - **Round Result & Real Distance View (`#result-modal`, `#result-map`)**:
[frontend]     - Submits guess to `POST /api/guess` and displays the exact real distance (`distanceFormatted` in `m` / `km` plus `distanceMeters`) and round score (`+0` to `+5,000` pts).
[frontend]     - Interactive OpenStreetMap result map plots the Actual Location marker, the User's Guess marker, a dashed connecting line, and a permanent midpoint distance tooltip.
[frontend]   - **Final Summary Screen (`#summary-modal`)**: Displays total score out of 25,000, average real distance error, best round, and per-round breakdown table.
